## 一、失败会怎么报

抓不到时，报出来的**原因**比"抓不到"本身更重要。
以下都有专门的判定，不会含糊成"没有数据"：

| 真实情况 | 报什么 | 为什么重要 |
|---|---|---|
| 页面是空壳，靠 JS 渲染 | `needs-browser`：这一页 HTML 里没有数据，去抓接口 | 否则会一直改选择器，而怎么改都取不到 |
| 接口 HTTP 200 但 body 是错误码 | `api-blocked`：接口返回错误码，被拒了 | 否则会被误报成"规则没命中"，让人以为是自己写错了 |
| 需要登录 / cookie 失效 | `credential`：需要登录态，请提供 cookie | 明确给出下一步，而不是笼统报错 |
| 风控 / 挑战页 | `blocked`：站点主动拒绝自动化访问 | 说明换参数没用，别白试 |
| 连不上 / 超时 | `network` / `timeout`：问题在网络，不在参数 | 避免在参数上瞎试 |
| 规则真的没匹配到 | `empty`：指出是哪条选择器/路径没命中 | 自我校准的唯一信号 |
| 缺 URL 占位符参数 | `input`：说清缺哪个参数，**在发请求之前就失败** | 否则会请求一个参数为空的地址，拿到无关结果还看不出来 |

**同类失败到达阈值后，会换成固定话术并标记"不要再试"** ——
避免"每次失败都给一条新建议"导致调用方空转十几分钟。

阈值按类别不同：凭据 / 被拦 / 风控 / 空壳页 / 空结果 **1 次**；
网络 / 超时 **2 次**。成功一次就清零，换目标站重新计数。

## 二、看着成功但其实没抓到

这是最危险的一类，工具专门做了防护：

| 形态 | 工具的反应 |
|---|---|
| 选择器一条都没命中 | 判成 `empty` 失败，**不会**返回空数组当作成功 |
| 页面是空壳 | 判成 `needs-browser`，并让你去抓接口 |
| 接口返回错误码 | 判成 `api-blocked`，不会报"没数据" |
| 抓到的全是数据集里已有的 | 明确报"数据集里都已经有了（新增 0 条）"，**不报成功** |
| 已经翻到底了又抓一次 | 明确说"没有更多了"，不会从头再抓一遍 |

**反过来，要留意的**："命中 0 条"不等于抓取成功——这是最常见的
"看着在跑其实什么也没拿到"的形态。

## 三、抓不了什么（请先读这一段）

通用 ≠ 万能。下面这些**做不到**，而且不是实现问题：

| 情形 | 结论 | 原因 |
|---|---|---|
| 强反爬（Cloudflare 类挑战、指纹风控） | 抓不了 | 对方主动设计来阻止自动化，是持续的军备竞赛 |
| 付费墙 / DRM 内容 | 抓不了，也不该抓 | 越过内容授权边界 |
| 需要逆向的请求签名 / 加密参数 | 抓不了 | 要破解目标站前端逻辑，不在本工具范围；工具会报 `api-blocked` 而不是假装没数据 |
| 必须登录但未提供 cookie | 抓不了 | 工具会明确报告"需要登录态"，不代为登录 |
| 登录态已失效 / 设备绑定 | 抓不了 | 只会提示重新提供 cookie |
| 画布 / WebGL 渲染、需人工验证码 | 抓不了 | 超出抓取工具范围 |
| 地区限制 | 需自备代理 | **本工具不提供代理** |
| 靠 JS 渲染且接口不可达 | 抓不了 | 没有浏览器渲染通道，只能用接口 |

**适配器负责"拿到之后怎么解析"，不负责"能不能拿到"。** 这两件事必须分清。

### 已知的边界与限制

- **只支持 CSS 选择器**，不支持 XPath
- **数据跑完才落盘**：单次抓取中途失败会丢掉这一批，大批量建议分批
- **`limit` 是"最多取多少"**，不是"保证取到多少"
- **没有自动重试**：个别站点会偶发 412/风控，一次失败就整体失败。
  降低单批数量、加大 `delayMs` 比反复重试划算
- **接口返回的统计数字可能是缓存值**：实测同一个视频的播放数，
  后抓到的反而更低。当趋势看可以，当精确值不行

## 四、常见操作问题

### 装了插件但看不到 `crawlkit_` 工具

1. 先在包目录跑 `node check.js`，确认包本身完好（应显示 10/10）
2. 检查「插件」里条目指向的路径是否正确、是否在 bundle 列表里
3. 重启 DSH

### 新对话里说"还没有任何适配器"，但我明明有

**数据目录跟着对话的工作目录走。** 换个工作目录开会话就看不到之前的数据。
解决：在同一个工作目录下开对话，或用配置里 `dataRoot` 写**绝对路径**。
用 `crawlkit_selfcheck` 可以看到实际的数据目录在哪。

### 适配器报"文件名与规则里的 id 不一致"

适配器**按 `id` 索引**，改文件名不会改 `id`。
把文件名改成 `<id>.json`，或把规则里的 `id` 改成文件名。

### 试跑（`action=test`）报 400 / 失败，但正式抓取正常

已在 0.12.0 修复：试跑与正式抓取现在走同一套请求构造。
若仍不一致，请确认版本。

### 写 POST 适配器没有效果

已在 0.12.0 实现（此前校验允许 POST 但实际发的是 GET）。

### `parse:"text"` 报"必须是 none / number / date / lower"

已在 0.12.0 支持 `text`。旧版本会拒绝这类适配器，
表现为 `get` / `run` 报"没有这个适配器"。

### 规则写对了但字段全是空的

两种常见原因：

1. **字段选择器写成了绝对链**（`body > div > h3`）——它在条目内取不到东西，
   一律相对"每一条"写（`h3`）
2. **字段选择器就是条目自己的选择器**——字段是在条目**内部**查找的，查不到自己。
   要取条目本身，把 `sel` 留空

`action=test` 会报告"哪些字段在所有样本里都是空的"，用它定位。

### 换了查询词就要重建适配器

把查询词写成 URL 占位符（`{keyword}`），用 `params` 传值 —— 见
[使用指南 · 参数化](使用指南.md#参数化一个适配器服务任意查询)。

## 五、合规边界

- 只抓**公开数据**；不要用它获取未授权内容
- 遵守目标站的 robots 与使用条款
- **主动限速**（`delayMs`），不要给目标站造成压力
- 不绕过付费墙、不绕过访问控制
- **使用者对自己抓取行为的合规性负责**
