# 决策记录

> 为什么这样设计。每条都记下**当时的取舍和代价**，避免以后重新讨论一遍。
> 结构与原理见 [架构说明](架构说明.md) / [原理](原理.md)。

---

## 1. 适配器是纯数据，不是代码

**决定**：规则里不允许出现脚本，没有逃生门。

**为什么**：能审查（一眼看懂、能 diff）、能分享（无安全风险、直接贴给别人）、
能由 agent 生成（不需要执行任何东西）、仓库天然干净（站点知识落在插件之外）。

**代价**：表达能力受限。一些需要条件分支、字符串加工的复杂抓取做不了。

**当时否掉的替代方案**：允许在规则里写一小段 JS。
否掉的理由是它把上面四条好处一次性全丢掉，而且"生成代码"比"生成数据"危险得多。

---

## 2. 零第三方依赖

**决定**：只用 Node 内置能力，HTML 解析器和 JSON 路径都自己实现。

**为什么**：安装时不需要 `npm install`，不会因为依赖升级而失效，
不会有供应链风险，包的体积和行为都可预期。

**代价**：自己实现的部分只能覆盖"抓取真正用得上"的子集——
CSS 选择器只支持常见语法，JSON 路径只有 `data.list` / `[0]` / `[*]` / 深层字段。
**不支持 XPath。**

---

## 3. 不做浏览器渲染通道

**决定**：不内置无头浏览器。

**为什么**：那会把零依赖和体积优势全部抹掉（一个 Chromium 上百 MB），
而且需要持续的维护。当前环境的限制也使这条路走不通。

**代价**：靠 JS 渲染、且接口不可达的站点抓不了。这类站点报 `needs-browser`，
并引导去抓接口——**这是刻意的方向指引**，因为改选择器是死路。

---

## 4. 不逆向请求签名

**决定**：不实现目标站的签名算法。

**为什么**：那要求破解目标站的前端逻辑，属于另一个项目，
而且会随着目标站更新不断失效。

**代价**：需要签名的接口抓不了。工具会报 `api-blocked` 并说明"换参数不会通过"，
而不是含糊成"没有数据"。

---

## 5. 不提供代理

**决定**：不内置代理支持。

**为什么**：网络出口该由使用者自己决定，工具不该插手。
而且在报错里写"加代理参数"只会让调用方去瞎试端口。

**代价**：地区限制的站点需要使用者自己在网络层解决。

---

## 6. 数据写在会话工作区，不写在插件目录

**决定**：`<会话工作区>/crawlkit-data/`。

**为什么**：插件目录永远干净（更新插件不会碰数据）、用户总能找到自己的数据、
同一个 DSH 里不同工作区的会话各写各的。

**代价**：**换个工作目录开会话就看不到之前的数据**——这是个真实的使用陷阱，
看起来像 bug（"我明明有适配器，它说没有"）。所以要共用一份数据时用绝对路径的 `dataRoot`。

**踩坑记录**：这个落点改过两次。第一次用了全局表，第二次用了 `process.cwd()`——
桌面版下那是 profile 目录，数据写到了用户找不到的地方。
最终确定的权威来源是 `agent.session.header.cwd`。

---

## 7. 自己实现 DSL → JSON Schema 的编译器

**决定**：不用 `@deepseek-ai/dsh-tools` 提供的编译器，自己在 `lib/schema.js` 里实现。

**为什么**：那个包**从插件安装位置解析不到**（实测 `MODULE_NOT_FOUND`）。
用它就等于要求用户额外装依赖，违背第 2 条。

**代价**：DSH 升级如果改了 schema 约定，这里要跟着改。
`node check.js` 会守住"工具 schema 是否合法"这一条。

---

## 8. "命中 0 条"必须显式失败

**决定**：选择器没命中时判成失败，而不是返回空数组。

**为什么**：成熟爬虫库通常静默返回空，而 agent 生成适配器时最需要的
恰恰是"你这条选择器一条都没命中"这个信号。没有它，生成适配器就是空话。

**代价**：某些"这一页本来就可能是空"的场景会报失败。
但那通常也确实是需要知道的信息。

---

## 9. 失败分类独立成模块，并设阈值升级

**决定**：`failure.js` 专门做失败分类，同类失败到阈值后换成固定话术并标记"不要再试"。

**为什么**：单次超时又长，若每次都回一句"换个参数再试"，
`超时 × 重试次数` 会累加成十几分钟空转。

**踩坑记录**：这套机制曾**定义了却从未接线**——阈值、话术、`stopRetrying` 标记都写好了，
但 `FailureTracker` 和 `escalate()` 全项目零引用，于是"不要再试"这句话永远不会出现。
文档还声称它在工作。**这是"文档说有、实际没有"最典型的一次**，
后来靠 `node check.js` 之外的真实使用才发现。

---

## 10. 展示层的清洗不碰落盘数据

**决定**：长字段截断与注入清洗**只作用于送进模型的文本**，数据集里保持原文。

**为什么**：这两件事混在一起，用户拿到的数据就会被展示层的防护改写——
而用户要的是原文。

**代价**：需要两套路径（落盘一套、展示一套），稍有重复。
但"用户的数据不被偷偷改动"比省几行代码重要。

---

## 11. 文档分家：README 只放招牌

**决定**：README 只有五段（项目名、简介、核心特性、快速开始、许可证），
其余全部进 `docs/`。

**为什么**：README 是给人"决定要不要用"的，不是给人"学完整个项目"的。
上一版 README 膨胀到 300 多行、24 个章节，结果首页信息过载、
同一主题说了两遍、改动要翻很久。

**代价**：新用户要多点一次才能看到细节。用 README 里的文档索引弥补。
